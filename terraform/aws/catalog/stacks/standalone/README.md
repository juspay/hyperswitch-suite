# Standalone (self-host) stack

Single-region Terragrunt Stack for self-hosting Hyperswitch in your own AWS
account. It composes six catalog units:

| Phase | Unit | Path (state key) |
|---|---|---|
| 1 | `database` (Aurora PostgreSQL) | `database` |
| 1 | `elasticache` (Valkey, cluster mode) | `elasticache` |
| 1 | `efs` (superposition backup FS) | `efs` |
| 2 | `eks-01` (EKS cluster + node groups) | `application-stack/eks-01` |
| 3 | `eks-resources` (storage classes, autoscaler) | `application-stack/eks-resources` |
| 4 | `security-rules` (SG rule matrix) | `security-rules` |

## Prerequisites

- An existing VPC with database, elasticache, private worker and (optionally
  separate) control-plane subnets. Public subnets for load balancers must be
  tagged `kubernetes.io/role/elb = 1`, private ones
  `kubernetes.io/role/internal-elb = 1`.
- An S3 bucket for terraform state (versioned, encrypted). See
  `terraform/aws/bootstrap/` for a reference.
- Terragrunt >= 0.80 (Terragrunt Stacks + S3 native locking) and
  OpenTofu/Terraform.

## Usage

Do not use this directory directly. Run `scripts/self-host/generate.sh` from
the repo root — it prompts for your environment values and renders
`terraform/aws/live/<env>/terragrunt.stack.hcl` with a `stack` block pointing
here. Then:

```bash
cd terraform/aws/live/<env>
terragrunt stack generate       # renders the unit tree into <region>/
git add . && git commit         # the generated tree is meant to be committed
cd <region>
terragrunt run-all apply        # applies units in dependency order
```

The `path` values above are load-bearing: the ArgoCD applications generated by
`scripts/self-host/` read terraform outputs from
`s3://<state-bucket>/<env>/<region>/<path>/terraform.tfstate` via the tfstate
helm plugin. Do not rename unit paths without updating the ArgoCD templates.
